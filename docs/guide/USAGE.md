## 先選介面

| 你的情況 | 用哪個 |
|---|---|
| 不寫程式、只想描述需求拿成果 | **桌面 App** |
| 平常就在 VS Code 裡工作 | **VS Code extension**（控制台面板） |
| 想看到最詳細的分工證據與 token 用量 | **VS Code 控制台**（桌面 App 只顯示 phase / 迭代 / 成本） |
| 要在沒有 GUI 的機器上跑 | 直接用 CLI：在專案資料夾開 Claude Code 打 `/start` |

兩者底層是同一條 pipeline、同一份 `log/events.jsonl`，所以你在哪邊看進度都一致。

## 桌面 App

### 安裝

到 [Releases](https://github.com/gsinvest017-ai/gs-codex-auto-ai/releases) 下載
`CodexAutoAI-setup-x.y.z.exe` → 安裝 → 點桌面的金色圖示。

### 畫面上有什麼

由上到下六個區塊：

**① 更新橫幅**（平常隱藏）
啟動時背景比對 GitHub Release 的最新 `app-v*`，有新版才跳出金色橫幅。
按 **⬇ 立即更新** 會自動下載安裝檔並啟動更新；按 **✕** 忽略這次。

**② 環境檢查卡**
六項逐一顯示，圓點顏色代表狀態（綠＝就緒、紅＝關鍵項缺失、金＝非關鍵項缺失）：

| 項目 | 關鍵？ | 缺了會怎樣 |
|---|---|---|
| Claude Code | **是** | 不能啟動（啟動鈕會鎖住） |
| OpenAI Codex | **是** | 不能啟動 |
| Node.js | 否 | Codex 需要它，實務上仍建議裝 |
| Git | 否 | 產出無法版控 |
| GitHub CLI | 否 | 自動更新／private repo 會失敗 |
| Python | 否 | 打包版內建，開發版需要 |

- **🔧 設定 / 修復** — 先偵測環境，關鍵項都就緒就直接回報、**不開終端機**；
  有缺才開終端機跑 `setup.cmd` / `setup.sh`（登入、裝 Codex、啟用 hooks）。可以安全重跑。
- **↻ 重新檢查** — 在終端機完成登入後按這個刷新圓點。

**③ 需求輸入框**
用一句白話描述你要的東西，例如「做一個記帳 CLI 工具，資料存 SQLite」。
不用寫規格，Phase 2 會反問你細節。

> 輸入內容會先過一層清理（`_safe_prompt`）：引號與反引號移除，`$` `&` `%` `!` `;` `<` `>`
> 轉成全形。因為需求要經過一層 shell，不清理的話 `$(...)` 會被當指令執行。
> 中文與全形標點（`（）「」`）完全不受影響，`100%` 會變成 `100％`。

**④ 非停模式勾選框**
勾了等於在需求前面加 `/autopilot on` — 連回合之間都不停，一路跑到交付。
詳見 [中止與非停模式](#中止與非停模式)。

**⑤ 啟動**
- **🚀 啟動新任務（先產規格再開發）** — 唯一的啟動入口。先用 gs-spec-forge 把你那句
  話變成正式規格檔，再拿該規格跑七階段。
- **🖥 開啟內嵌終端機** — 只開終端機面板、不建 session，讓你自己挑要開 Claude、
  Codex 還是一般終端機。見 [內嵌終端機](#內嵌終端機)。

> 舊版還有一顆「直接把需求丟給 claude」的按鈕，已移除：那條路跳過規格階段，
> 等於繞開本框架的前半段，而且兩顆並排只會讓人不知道該按哪顆。

「**內嵌終端機**」勾選框預設是開的：按啟動時 session 會開在 App 右欄的分頁裡，
而不是另外跳一個原生終端機視窗。取消勾選（或這台機器 PTY 不可用）才會退回外部終端機。

**⑥ Pipeline 進度卡**
每 2 秒讀一次 `log/events.jsonl`，顯示 `Phase N/7 ▓▓▓░░░░ 階段名` 加一行細節
（已完成階段、當前迭代、累計成本、最後錯誤）。顏色：金＝進行中、綠＝完成、紅＝失敗／升級。

- **■ 中止** — 只在「進行中」時可按。見 [中止與非停模式](#中止與非停模式)。

### 一次完整流程

1. 開 App → 看環境檢查 → 不全綠就按 **🔧 設定 / 修復**，照終端機指示登入。
2. 按 **↻ 重新檢查**，確認關鍵兩項（Claude Code / OpenAI Codex）是綠的。
3. 在輸入框打需求。要全程無人介入就勾 **非停模式**。
4. 按 **🚀 啟動新任務（先產規格再開發）**。App 會先產規格檔，再在右欄的內嵌
   面板開一個 Claude 分頁跑 pipeline。
5. 回到 App 看**進度卡**。Phase 2 可能會在終端機問你需求細節。
6. 跑到 Phase 7 交付後，程式在 `src/`、測試在 `tests/`、報告在 `docs/`。

## VS Code extension

### 安裝

到 [Releases](https://github.com/gsinvest017-ai/gs-codex-auto-ai/releases) 下載
`codexautoai-x.y.z.vsix`，然後二選一：

```bash
code --install-extension codexautoai-x.y.z.vsix
```

或 VS Code 擴充功能面板 → 右上 `…` → **Install from VSIX…**。

### 控制台面板（主要入口）

裝好後左側活動列會出現 **CodexAutoAI** 圖示，點它開啟常駐控制台。
不想碰指令面板的人只要用這個就夠。面板內容：

| 區塊 | 是什麼 |
|---|---|
| **你想做什麼？** | 需求輸入框 + 非停模式勾選 |
| **🚀 啟動新任務（先產規格再開發）** | 產規格 → 在內嵌面板跑 pipeline |
| **▶ 從 spec 開始** | 先產規格再跑 |
| **七階段進度** | 進度條 + 當前階段 + 迭代次數 + 累計成本 |
| **分工證據** | Claude 呼叫次數／token 與 Codex 呼叫次數，證明「規劃走 Claude、實作走 Codex」 |
| **分工警示** | 已進入 Phase 5 卻沒有任何 Codex 呼叫時亮起——代表可能在燒 Claude 額度寫程式碼 |
| **🌐 即時預覽網頁 UI** | 產出有前端時一鍵在 VS Code 內開啟 |
| **顯示終端機** | 背景終端機的逃生口，想看原始輸出時用 |

面板標題列右上有**停止圖示**＝中止（等同 `CodexAutoAI: 中止` 指令）。

### 七個指令（`Ctrl`/`Cmd` + `Shift` + `P`，打 `CodexAutoAI`）

| 指令 | 用途 |
|---|---|
| **開啟控制台（免終端機 GUI）** | 上面那個面板 |
| **安裝設定（初始化 + 登入修復，一鍵）** | 把框架放進資料夾（自帶快照，不必先 clone；既有專案會更新框架核心）＋ 裝／登入 Claude、Codex、gh、Live Preview、啟用 hooks。環境已就緒時直接回報、不開終端機。可安全重跑 |
| **啟動新任務（先產規格再開發）** | 輸入需求 → 選「一般／非停」→ 產規格 → 跑 pipeline |
| **啟動新任務：從 spec 開始** | 先用 gs-spec-forge 產規格再跑 |
| **即時預覽網頁 UI（內嵌）** | Live Preview → Simple Browser → 自動起 server，三層降級 |
| **檢查更新** | 比對最新 `ext-v*`；啟動時也會自動查（每天一次） |
| **中止（下一個回合邊界停止）** | 見 [中止與非停模式](#中止與非停模式) |

### 相關設定（Settings 搜 `codexautoai`）

| 設定 | 預設 | 作用 |
|---|---|---|
| `defaultRequirement` | 記帳 CLI 範例 | 啟動輸入框的預設值 |
| `checkForUpdates` | `true` | 啟動時自動查新版 |
| `applyGlobalSettings` | `true` | 開 extension 時暫時把 full-auto 友善設定套到全域 Claude/Codex，關閉 VS Code 時自動還原 |
| `skipSetupWhenReady` | `true` | 環境已就緒就跳過 setup、不開終端機 |
| `specForgeCmd` | `spec-forge` | 「從 spec 開始」呼叫的 CLI |

## 專案資料夾

pipeline 的產出（`src/` `tests/` `docs/` `log/`）都落在**專案資料夾**，預設是
`~/CodexAutoAI`，可以在主畫面的「專案資料夾」卡片按「📂 變更」改。設定記在
`~/.codexautoai/desktop.json`，重裝 App 不會掉。

> 舊版寫死成 App 的安裝目錄，所以你的專案會被寫進 `%LOCALAPPDATA%\CodexAutoAI`，
> 而且每個任務共用同一份 `log/`——進度卡會顯示上一輪殘留的 Phase。現在不會了。

還有 session 在跑時不能換（換了新舊 session 會跑在不同目錄），請先關掉再改。

## 內嵌終端機

以前每開一個 session 就會跳出一個**外部的原生終端機視窗**：開三個任務就有三個視窗
散在桌面上，關掉 App 它們也不會跟著收，而且 App 完全看不到裡面在跑什麼。

現在 session 開在 **App 視窗的右半欄**、用分頁管理。

### 怎麼開

兩條路都可以：

* 勾著「內嵌終端機」按 **🚀 啟動新任務** → 直接開一個 Claude 分頁並帶入你的需求。
* 按 **🖥 開啟內嵌終端機** → 開空的終端機面板，再自己按「＋ 新增」挑種類。

任一條路都會把視窗往右撐開，左邊維持原本的控制欄、右邊是終端機。右上角有兩個鈕：

* **⤢ 收合** — 收掉右欄、視窗變回原本的寬度。**session 不會被關掉**，之後再開會接回。
* **⇱ 另開視窗** — 把終端機丟回獨立視窗（想拉到第二螢幕時用）。

> 內嵌到 App 視窗內需要 Windows 加上 Edge 或 Chrome（Windows 10/11 都內建 Edge）。
> 兩者缺一時會自動退回獨立視窗開啟，狀態列會寫明原因——功能一樣，只是不在同一個視窗裡。

### 畫面

* **上方分頁列** — 每個 session 一個分頁，顯示種類與編號（例如 `Claude · s1`）。
  綠點＝還活著，紅點＝已結束。點 `✕` 關掉那個 session（會真的把行程收掉）。
* **＋ 新增** — 展開建立面板：選種類（Claude / Codex / 終端機）、選填需求，按「開啟」。
  沒安裝的種類會標成「（未安裝）」且不能選。
* **版面列** — 四種排法：`▢` 單一、`▥` 左右並排、`▤` 上下堆疊、`⊞` 四格。
  多面板時有金色外框的那一格是「焦點格」，**點上方分頁就會把該 session 放進焦點格**；
  點某一格也可以把焦點移過去。同一個 session 不會同時出現在兩格。
  分頁的文字顏色會告訴你它現在有沒有被顯示（金色＝正在某一格裡）。
* **終端機區** — 真正的 pty，ANSI 顏色、游標、TUI（Claude 的互動介面）都正常運作，
  可以直接打字、按 Ctrl+C、貼上。視窗縮放與版面切換都會自動把新尺寸同步給 pty。

### 幾個實際會遇到的細節

**切走再切回不會掉畫面。** 每個 session 都保留最近 256 KB 的輸出，重新連上時會先
重播再接續即時串流。

**收合右欄再展開，session 還在。** 服務的生命週期跟著 App 而不是這個面板，
所以重新打開（或重新整理頁面）會自動接回所有還在跑的 session，畫面內容也會補回來。

**關掉 App 會一併收掉所有 session。** 這是刻意的——pty 底下還有 node 子行程，不收
會變孤兒。所以別把內嵌終端機當成「關掉 App 還會繼續跑」的背景工作。

**資料夾信任確認會自動略過。** 新的專案資料夾第一次開 session 時，claude 本來會停在
「Yes, I trust this folder」等你按 Enter。App 會先把**你自己選的那個專案資料夾**標記成
已信任（寫進 `~/.claude.json`），不碰其他任何專案。

**打不了字的話按「⇱ 另開視窗」。** 內嵌面板是把瀏覽器視窗塞進 App 視窗裡的，
鍵盤焦點不一定過得去；點一下終端機區會嘗試把焦點交過去，若仍然無法輸入，
用「⇱ 另開視窗」把終端機丟回獨立視窗就一定能操作。

**同時最多 12 個 session。** 這是防手滑（或惡意網頁）把機器資源吃光的上限。

**需要 Windows 10 1809 以上**（ConPTY）。太舊的系統會自動退回舊行為（外部終端機），
並在狀態列說明原因。

**這是本機服務，只綁 127.0.0.1。** 它能生出行程，所以有一次性 token、擋非 loopback
的 Host、只允許固定種類（不接受任意指令）這幾道防線。網址帶著 token，不要外流。

## 怎麼讀進度

七個階段（進度條的每一格）：

| Phase | 名稱 | 在做什麼 |
|---|---|---|
| 0 | 初始化 | 建立資料夾結構 |
| 1 | 環境檢查 | 確認 Codex 可用 |
| 2 | 需求分析 | **唯一可能停下來問你**的階段 |
| 3 | 架構設計 | 拆解 function、產出架構文件 |
| 4 | 審查 | Codex 審查架構與需求是否契合（不通過會循環） |
| 5 | 並行開發 | Codex 實際寫 `src/` |
| 6 | 測試 | 跑測試，失敗進入有界修復迴圈 |
| 7 | 交付 | 產出報告與執行說明 |

三個介面（終端機 `tools/progress.py`、桌面進度卡、VS Code 控制台）讀的是**同一份**
`log/events.jsonl`，所以不會出現互相矛盾的說法。

**「當前迭代」** 指 Phase 4 或 Phase 6 的修復迴圈跑到第幾輪。守衛上限是 3 輪：
超過、或連續兩輪沒有進展、或超出 token 預算，就會升級（escalate）並停下來通知你，
**不會無限重試**。

**「累計成本」** 是 pipeline 自己記的估算值，用來看趨勢，不是帳單。

## 中止與非停模式

### 非停模式（autopilot）

勾選後 pipeline 連回合之間都不停，一路跑到交付。它靠 Stop hook
（`tools/autopilot/cont.py`）在每次想結束時把模型擋回去繼續做。

**仍然會停的情況**（七道安全閥，依序判斷）：

1. Claude 自己的續跑迴圈已在進行
2. 本 session 沒開 autopilot
3. 任務完成（done sentinel）
4. **你按了中止**（`log/abort.flag`）
5. 續跑次數達上限（預設 30）
6. **token 用量閘門擋下**——見下
7. 以上都沒有才續跑

另外 `commit` / `push` / 刪除這類不可逆操作仍會停下來問你。

### token 用量閘門

`usage_gate.toml`（預設**啟用**，門檻 60%）。它讀 `ccusage` 的資料，拿「歷史峰值 5h
block」當 100%，當前用量超過門檻就不再續跑，把額度留給你手動工作。

- 沒裝 `ccusage` 的機器一律 **fail-open**（照跑），所以開著不會讓任何人卡住。
- 臨時關閉：環境變數 `CODEXAUTOAI_USAGE_GATE=0`
- 手動查現況：`python tools/usage_gate.py`

> 為什麼預設開：autopilot 續跑、`claude -p`、以及 GitHub Actions 上的
> claude-code-action **都從同一份 Pro/Max 訂閱額度扣**（原訂 2026-06-15 拆成獨立
> Agent SDK credit 的計畫已取消）。不設閘門的話，一輪長時間 autopilot 可能把你當天
> 要用的額度吃光。

### 中止的真正語意（重要）

按「中止」＝寫一個 `log/abort.flag` 檔案，Stop hook 在**下一個回合邊界**看到它就停。

**它殺不掉正在執行的 `codex exec` 子行程。** 所以如果 Codex 正在寫一個大檔案，
按下中止後它會把那次寫完，然後才停。想立刻中斷只能去終端機按 `Ctrl-C`。

旗標是**一次性**的：用掉就刪除，不影響你下一次啟動。

## 常見狀況

**啟動鈕是灰的**
關鍵兩項（Claude Code / OpenAI Codex）沒就緒。按 **🔧 設定 / 修復** → 照終端機登入 → **↻ 重新檢查**。

**進度卡一直停在「尚未開始」**
`log/events.jsonl` 還沒產生。確認終端機真的有跑起來（VS Code 用「顯示終端機」看）。

**進度顯示一個你沒啟動過的 run**
`log/` 有殘留狀態（例如跑過測試）。刪掉 `log/state.json` 與 `log/events.jsonl` 即可。
順帶一提：stale 的 `state.json` 也會讓 `enforce_build_codex` 誤以為正在 build。

**進度卡顯示紅色「失敗／升級」**
修復迴圈的守衛觸發了。細節看 `log/` 下最新的報告，或終端機輸出的 escalation 原因。
`fixer_failed` 代表 Codex 沒跑成功（額度／未登入／sandbox 拒寫），
**不是**「測試修不動」——這兩種原因會分開標示。

**VS Code 控制台亮「分工警示」**
已進入 Phase 5 卻沒有任何 Codex 呼叫，代表可能在用 Claude 直接寫程式碼。
正常情況下 `src/` 的實作應該全部由 Codex 產生（有 PreToolUse hook 把關）。

**autopilot 自己停了，log 說「用量閘門擋下續跑」**
額度到門檻了。等 5h block 重置，或臨時設 `CODEXAUTOAI_USAGE_GATE=0` 覆寫。
